# Mindmaker Homepage Comparison Matrix

Status: active design gate

Baseline checked: 2026-08-12

Production baseline: https://www.themindmaker.ai/

Component-led mock: prototypes/mindmaker-homepage-component-led-v2.html

## Rule

The next version must improve the job of each section, not merely look newer or contain fewer words. When a replacement is weaker than production on a useful quality, retain or reshape the production behaviour.

V3 is rejected. It is not the new baseline. The current coded site is the design and interaction asset library until a replacement wins visibly and functionally side by side.

Scores are directional design evidence, not research findings:

- 1: fails the job
- 2: materially weak
- 3: works with clear problems
- 4: strong
- 5: exceptional and verified

## Rejection record: V3

Krish's first reactions:

- "this experience feels so not magic at all"
- "leaves big blank boxes at the start, broken components and no real wow moment"
- "the big text wraps so awkwardly it makes the entire section longer unnecessarily"
- "your v3 just looks completely generic, anyone could make that in 3 mins"
- "you might have binned a lot of really good visual design"

Root causes:

| Owner | Failure |
| --- | --- |
| Product rule | The sample experience made the visitor wait for the page to become useful. |
| Interaction | A form beside an empty result box is a familiar generator pattern, not an ownable Mindmaker interaction. |
| Design system | Oversized editorial type, borders and cream panels replaced the stronger existing motion and spatial language with a fashionable template. |
| Copy | Internal prototype notes appeared in the experience and the headline inflated a simple promise into three awkward lines. |
| Data truth | The mock implied a company read while only fixed local profiles existed. |
| Frame execution | Phantom height, inactive controls and blank first paint made the concept look broken. |

Decision: stop refining this conceptual spine. Return to fresh interaction divergence and use the current site as the preservation benchmark.

## Section decisions

### Navigation

Retain the wordmark, theme behaviour and access to useful routes. Show only buying-path links in the main navigation. Move supporting routes to the footer or a quiet drawer. Use “Book a fit call” as the only filled action.

### Hero

Production strengths are immediate motion, ink and emerald contrast, and recognisable buyer statements. Its weaknesses are a changing proposition, four starting routes and familiar particle decoration.

V2 improves message clarity, real imagery and action hierarchy. It regresses because the collage does not truly build, CTRL is not explained through interaction, and the typography splits into several voices.

V3 must keep V2's message and imagery, build the evidence wall in a short meaningful sequence, let the visitor inspect one CTRL item and use one working type family.

### Problem framing

Production flip cards create discovery, but their future claims are broad and every card repeats a sales action. Preserve tap-to-reveal discovery. Reframe the cards as current business pressures. Let the reverse show the decision Mindmaker would test.

### Intelligent entry

Production contains express and full diagnosis modes, voice input, company enrichment, live data, structured output and session handoff. It duplicates the entry job and still routes towards old offers.

V2's fixed sample choices are a major regression.

V3 must use one company-domain input, predict two or three pressures from public evidence and build the decision, evidence, unknown and 21-day test in place. Keep voice, haptics, co-branding, source marks and reduced-motion support. Ask for email only after value.

### How Mindmaker changes the business

Production's CTRL, architecture, live prices and memory evidence prove that Krish builds, but the evidence is split across three sections and arrives in technical language.

V3 must combine the evidence into one working-system section organised by product, price, place in the market and team. Each choice reveals a real CTRL crop, method and business result. Live data stays only where it changes the conclusion.

### Sprint

Production's bounded work reduces dependency fears, but two offers create an early choice. Present one focused Sprint, show the three-week sequence and make the handback visible. Keep the option to stop after the decision or build with the team without presenting two competing cards.

### Results

Production has rich expandable case content but hides it in a carousel and uses records outside the approved proof source. V2 uses approved stories and a stronger editorial hierarchy but loses the case-file reveal.

V3 must use a static editorial grid for scanning and open each story in place with problem, decision, work and outcome. Use only the eight verified stories.

### Krish

Keep the direct voice, useful operator evidence and links. Combine the scattered trust material into one section with a real conversation photograph, the shortest career facts, one approved reference and one optional working artefact or media drawer.

### Mindmaker Live and footer

Keep publication access and every useful supporting route. Move the subscription away from the buying journey. Use one branded publication URL and explain Built and Paid as article types there.

## Approval gate

V3 cannot be recommended until:

- No whole-page score is below both production and V2.
- Every retained production strength has a visible replacement.
- The intelligent entry demonstrates more than fixed sample text.
- The type system uses one working family plus the wordmark.
- Desktop and mobile each show three meaningful build moments.
- Reduced motion keeps all meaning.
- The approved proof source is the only source for public claims.
